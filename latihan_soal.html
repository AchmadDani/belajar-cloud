Pekan 1 & 3: Arsitektur Server Bobot: 20 Poin

Soal Esai 1: Mencegah Bottleneck pada Cluster Server 3-Tier

Sebuah platform e-commerce besar menggunakan arsitektur cluster server tiga tingkat (Tier 1: Switch/Load Balancer, Tier 2: Application Compute Servers, Tier 3: Database). Menjelang periode flash sale, traffic meningkat 10 kali lipat. Jelaskan mengapa Tier 1 berisiko menjadi titik kegagalan utama (bottleneck) jika seluruh komunikasi request dan reply melewatinya, serta jelaskan bagaimana mekanisme TCP Handoff dapat menyelesaikan masalah tersebut secara teknis!

Poin Kunci Jawaban Ujian:

  1. Penyebab Bottleneck di Tier 1: Pada model konvensional, switch tier-1 harus memproses dua arah: menerima request klien dan menyalurkan kembali seluruh paket respons berukuran besar dari tier-2 ke klien. Bandwidth dan CPU switch akan habis melayani aliran data balik (*asymmetry bandwidth* di mana reply jauh lebih besar dari request).
  2. Solusi dengan TCP Handoff: Klien menginisiasi koneksi TCP ke switch tier-1. Begitu switch mengidentifikasi server aplikasi tier-2 yang paling luang, koneksi soket TCP dialihkan (*handoff*) ke server tier-2 tersebut.
  3. Hasil Akhir: Server tier-2 langsung mengirimkan paket respons reply ke klien menggunakan IP switch sebagai source address. Switch tier-1 tidak lagi terbebani data respons dan bebas menerima request baru lainnya.
Pekan 5: Kausalitas & Jam Logis Bobot: 20 Poin

Soal Esai 2: Analisis Kausalitas: Lamport vs Vector Clocks

Dalam sistem terdistribusi terdapat tiga proses (P1, P2, P3). Mengapa nilai timestamp Lamport C(a) < C(b) tidak cukup untuk membuktikan bahwa event a terjadi sebelum event b secara kausal? Berikan penjelasan logis mengapa Vector Clocks mampu memberikan jaminan dua arah (a → b ⇔ V(a) < V(b)) dan bagaimana cara kerjanya mendeteksi kejadian konkuren!

Poin Kunci Jawaban Ujian:

  1. Kelemahan Lamport: Lamport Clock hanya menjamin relasi implikasi satu arah: jika a → b maka C(a) < C(b). Namun jika dua proses independen menaikkan jam lokalnya tanpa pernah bertukar pesan, bisa saja C(a) < C(b) padahal kedua event tersebut konkuren (*tidak ada hubungan sebab-akibat*).
  2. Keunggulan Vector Clocks: Setiap proses memegang array vektor yang mencatat jumlah kejadian yang diketahuinya pada seluruh proses lain. V(a) < V(b) hanya benar jika setiap elemen V(a)[k] ≤ V(b)[k] dan terdapat minimal satu elemen yang lebih kecil secara ketat.
  3. Deteksi Konkuren: Jika ada komponen vektor di mana V(a)[i] > V(b)[i] namun untuk indeks lain V(a)[j] < V(b)[j], sistem dapat secara definitif menyimpulkan bahwa event a dan b terjadi secara konkuren (tidak saling memengaruhi).
Pekan 7: Konsistensi & Gifford's Quorum Bobot: 20 Poin

Soal Esai 3: Perhitungan Gifford's Quorum & Trade-Off

Sebuah sistem basis data terdistribusi memiliki total N = 9 replika. Tim pengembang mengusulkan dua skenario konfigurasi kuorum:
- Skenario A: N_R = 3, N_W = 7
- Skenario B: N_R = 5, N_W = 4
Ujilah apakah kedua skenario tersebut memenuhi dua syarat mutlak aturan Gifford's Quorum! Jelaskan pula beban kerja seperti apa yang paling diuntungkan oleh Skenario A!

Poin Kunci Jawaban Ujian:

  1. Uji Skenario A (NR = 3, NW = 7, N = 9):
    - Syarat 1: NR + NW = 3 + 7 = 10 > 9 (MEMENUHI). Tidak ada Read-Write conflict.
    - Syarat 2: NW = 7 > 9/2 (4.5) (MEMENUHI). Tidak ada Write-Write conflict.
    Kesimpulan Skenario A VALID.
  2. Uji Skenario B (NR = 5, NW = 4, N = 9):
    - Syarat 1: NR + NW = 5 + 4 = 9 (GAGAL, karena tidak lebih besar dari 9, tidak ada jaminan overlap!).
    - Syarat 2: NW = 4 < 4.5 (GAGAL, tidak mencapai mayoritas mutlak).
    Kesimpulan Skenario B INVALID (dapat menyebabkan data usang terbaca dan inkonsistensi benturan tulis).
  3. Aplikasi Skenario A: Sangat ideal untuk beban kerja dengan rasio pembacaan tinggi (Read-Heavy workload) karena klien hanya butuh mengontak 3 server untuk membaca data mutakhir secara kilat.
Pekan 2 & 4: Komunikasi & Kopling Bobot: 20 Poin

Soal Esai 4: Perbandingan Arsitektur RPC vs Message-Oriented Middleware

Bandingkan pendekatan Remote Procedure Call (RPC) dengan Message-Oriented Middleware (MOM) berdasarkan dimensi: (a) Temporal Coupling, (b) Referential Coupling, (c) Penanganan kegagalan jaringan saat server tujuan sedang mati, dan (d) Contoh skenario sistem di mana MOM mutlak lebih unggul dibandingkan RPC!

Poin Kunci Jawaban Ujian:

  1. Temporal Coupling: RPC bersifat *temporal coupled* (caller dan callee harus sama-sama aktif saat panggilan berlangsung). MOM bersifat *temporal decoupled* (pengirim dan penerima tidak perlu aktif bersamaan).
  2. Referential Coupling: RPC umumnya *coupled* (klien harus mengetahui endpoint spesifik server). MOM bersifat *decoupled* (klien hanya mengirim pesan ke antrean/topic tanpa tahu siapa pemrosesnya).
  3. Penanganan Kegagalan: Pada RPC, jika server mati, pemanggilan gagal seketika (*fail/exception*). Pada MOM, pesan tersimpan aman di antrean persisten (*message queue*) dan akan diproses saat server menyala kembali.
  4. Skenario Keunggulan MOM: Pemrosesan transaksi checkout e-commerce (pembuatan invoice, notifikasi email, pengurangan stok gudang di sistem terpisah). Klien tidak boleh menunggu seluruh subsistem selesai bekerja.
Pekan 6: Resolusi Nama Bobot: 20 Poin

Soal Esai 5: Alur Resolusi DNS Iteratif vs Rekursif

Seorang mahasiswa mengakses informatika.ugm.ac.id melalui komputernya. Jelaskan perbedaan alur transmisi pesan jika DNS resolver menggunakan pendekatan Iterative Resolution dibandingkan dengan Recursive Resolution! Mengapa server DNS Global (Root & TLD) di internet publik umumnya menolak permintaan rekursif dan hanya melayani permintaan iteratif?

Poin Kunci Jawaban Ujian:

  1. Iterative: Klien resolver menghubungi server Root DNS. Root menjawab "saya tidak tahu, tapi ini alamat TLD .id". Klien lalu menghubungi server .id, yang menjawab "ini alamat server ac.id", demikian seterusnya sampai klien sendiri menemukan server otoritatif ugm.ac.id.
  2. Recursive: Klien resolver meminta ke server DNS lokal, dan server DNS lokal tersebut yang secara estafet menghubungi Root, TLD, hingga server otoritatif atas nama klien, lalu mengembalikan jawaban akhir ke klien.
  3. Alasan Root & TLD Menolak Rekursif: Skalabilitas dan keamanan (*resource exhaustion*). Jika miliaran komputer di seluruh dunia meminta Root DNS untuk melakukan pencarian rekursif, memori dan soket koneksi Root DNS akan langsung habis dalam hitungan detik. Dengan hanya melayani iteratif (langsung mengembalikan alamat server berikutnya), beban kerja Root DNS sangat ringan dan dapat diskalakan secara global.
Bagian 3

Strategi Menjawab Soal UTS Sistem Terdistribusi

Pola penilaian dosen dan kata kunci wajib yang harus muncul saat menjawab soal esai.

1. Selalu Sebutkan Asumsi Jaringan (Fallacies): Jika soal menanyakan kegagalan sistem atau alasan dibutuhkannya timeout/retry, sebutkan bahwa "jaringan tidak pernah 100% reliable, latensi tidak pernah nol, dan topologi selalu berubah".
2. Gunakan Rumus Matematis: Pada soal keandalan sebutkan MTBF = MTTF + MTTR; pada soal antrean sebutkan utilisasi U = λ / μ; pada soal kuorum sebutkan N_R + N_W > N dan N_W > N / 2. Dosen selalu mencari rumus ini dalam lembar jawaban.
3. Bedakan Istilah Kritis: Jangan sampai tertukar antara Fault vs Error vs Failure, Precision vs Accuracy, atau Decentralized vs Distributed. Gunakan definisi baku yang ada di cheat sheet modul.
