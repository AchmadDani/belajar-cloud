Soal No. 1 Sistem Terdistribusi
Total: 15 Poin
a. Distribution Transparency (5 poin)

Transparency adalah kemampuan sistem terdistribusi menyembunyikan fakta bahwa proses dan resource tersebar di beberapa komputer.

Tiga jenisnya:

  1. Access Transparency: menyembunyikan perbedaan cara mengakses dan representasi data.
  2. Location Transparency: menyembunyikan lokasi fisik suatu resource.
  3. Replication Transparency: menyembunyikan fakta bahwa suatu resource memiliki beberapa salinan (replica).
b. Scalability (5 poin)

Scalability adalah kemampuan sistem untuk berkembang dan menangani peningkatan pengguna, resource, atau cakupan tanpa penurunan performa yang signifikan.

Tiga aspek scalability:

  1. Size Scalability: kemampuan sistem menangani peningkatan jumlah pengguna, komputer, atau resource.
  2. Geographical Scalability: kemampuan sistem beroperasi secara efektif ketika komputer tersebar di wilayah geografis yang lebih luas, misalnya dari LAN ke WAN.
  3. Administrative Scalability: kemampuan sistem mengatasi perbedaan kebijakan dan pengelolaan antar-domain administrasi atau organisasi.
c. Klasifikasi Sistem Terdistribusi (5 poin)

Contoh: Cluster Computing, termasuk High-Performance Distributed Computing.

Cluster Computing adalah kumpulan komputer (node) yang terhubung melalui jaringan dan bekerja sama menyelesaikan tugas komputasi.

Termasuk sistem terdistribusi karena memenuhi tiga karakteristik:

  1. No Global Clock: setiap node memiliki clock lokal dan tidak ada satu global clock.
  2. Communication Between Processes: antar-node berkomunikasi dan bertukar pesan melalui jaringan.
  3. Resource Sharing: node berbagi resource seperti processing power dan storage.
Soal No. 2 Arsitektur Sistem
Total: 15 Poin
a. Contoh Arsitektur Sistem (5 poin)

Contoh: Three-Tier Architecture, yaitu arsitektur yang membagi sistem menjadi tiga lapisan.

Diagram Three-Tier Architecture (Presentation Layer → Application Layer → Data Layer)

Penjelasan:

  1. Presentation Layer: menangani tampilan dan interaksi pengguna.
  2. Application Layer: memproses logika dan fungsi aplikasi.
  3. Data Layer: menyimpan dan mengelola data aplikasi.
b. Hybrid System Architectures (5 poin)

Hybrid system architecture adalah arsitektur yang menggabungkan beberapa pendekatan sistem untuk memperoleh keunggulan masing-masing.

Jenis-jenisnya:

  1. Cloud Computing: menyediakan resource komputasi melalui internet dengan empat lapisan:
    • Hardware: processor, router, dan perangkat fisik.
    • Infrastructure: virtual server dan virtual storage.
    • Platform: layanan dan abstraksi untuk pengembangan aplikasi.
    • Application: aplikasi yang digunakan pengguna.
  2. Edge-Cloud Architecture: menggabungkan cloud dengan edge server yang ditempatkan lebih dekat ke pengguna untuk mengurangi latency dan mendukung kebutuhan bandwidth.
  3. Blockchain Architecture: sistem terdistribusi yang menyimpan data dalam blok yang saling terhubung dan bersifat immutable. Penambahan blok dilakukan melalui distributed consensus.
c. Blockchain: Immutable dan Security (5 poin)

Blockchain bersifat immutable karena blok disusun dalam rantai append-only, sehingga data yang sudah tercatat tidak dapat diubah begitu saja.

Keamanan blockchain didukung oleh:

  1. Cryptographic Hash: setiap blok memiliki hash yang terhubung dengan blok sebelumnya. Perubahan data akan mengubah hash dan merusak keterkaitan rantai.
  2. Distributed Consensus: penambahan blok harus melalui kesepakatan antarpartisipan.
  3. Replication: salinan blockchain disimpan oleh banyak node sehingga tidak bergantung pada satu server.

Dengan mekanisme tersebut, manipulasi data menjadi sangat sulit karena perubahan harus dapat diterima oleh jaringan.

Soal No. 3 Proses (15 poin)
Total: 15 Poin
a. Empat Perbedaan Process dan Thread (5 poin)
  1. Address Space: Process memiliki ruang alamat (memory) sendiri, sedangkan thread dalam satu process berbagi address space.
  2. Resource: Process memiliki resource sendiri, sedangkan thread berbagi resource milik process.
  3. Context Switching: Perpindahan antar-thread lebih ringan, sedangkan perpindahan antar-process lebih mahal karena melibatkan kernel.
  4. Komunikasi: Antar-process membutuhkan mekanisme komunikasi khusus (IPC), sedangkan antar-thread dapat berkomunikasi melalui shared memory.
b. Kerja Sama Thread dan Kernel (5 poin)

Thread dan kernel bekerja sama untuk mengatur eksekusi thread dan penggunaan CPU.

Contoh: Pada model kombinasi User-Level Thread dan Kernel-Level Thread:

  1. User thread dijalankan melalui kernel thread.
  2. Jika user thread melakukan system call yang blocking, kernel thread tersebut ikut terblokir.
  3. Kernel dapat menjadwalkan kernel thread lain yang memiliki user thread siap dijalankan.
  4. Dengan demikian, thread lain tetap dapat berjalan meskipun salah satu thread sedang menunggu I/O.

Contoh penggunaan: Web server menggunakan beberapa thread untuk melayani request client secara bersamaan. Kernel mengatur penjadwalan thread ketika terjadi operasi I/O.

c. Aplikasi Menghitung Luas dan Keliling Lingkaran Menggunakan Thread (5 poin)

Contoh program Python menggunakan dua thread untuk menghitung luas dan keliling lingkaran secara bersamaan.

import threading import math r = 7 def hitung_luas(): luas = math.pi * r ** 2 print("Luas:", luas) def hitung_keliling(): keliling = 2 * math.pi * r print("Keliling:", keliling) t1 = threading.Thread(target=hitung_luas) t2 = threading.Thread(target=hitung_keliling) t1.start() t2.start() t1.join() t2.join() print("Perhitungan selesai")

Penjelasan:

  1. Thread t1 menghitung luas lingkaran.
  2. Thread t2 menghitung keliling lingkaran.
  3. start() menjalankan kedua thread.
  4. join() menunggu kedua thread selesai.

Rumus:

  • Luas = π × r²
  • Keliling = 2 × π × r
Soal No. 4 Komunikasi (15 poin)
Total: 15 Poin
a. Dua Protokol pada Transport Layer (5 poin)
  1. TCP (Transmission Control Protocol): protokol connection-oriented yang menyediakan komunikasi reliable dan berbasis stream. Data dikirim secara berurutan dan memastikan pengiriman.
  2. UDP (User Datagram Protocol): protokol connectionless yang menggunakan datagram dengan mekanisme best-effort, sehingga tidak menjamin data sampai atau berurutan.
b. Transient dan Persistent Communication (5 poin)
  1. Transient Communication: pesan akan dibuang oleh communication server jika tidak dapat langsung diteruskan ke server berikutnya atau penerima. Pengirim dan penerima perlu aktif saat komunikasi berlangsung.
  2. Persistent Communication: pesan disimpan pada communication server sampai berhasil dikirimkan kepada penerima. Pengirim dan penerima tidak harus aktif secara bersamaan.
c. Message Broker (5 poin)

Message Broker adalah perantara komunikasi yang menangani pertukaran pesan antar-aplikasi dengan format atau protokol berbeda.

Fungsi utamanya:

  1. Message Transformation: mengubah format pesan agar sesuai dengan aplikasi tujuan.
  2. Application Gateway: menjadi penghubung antar-aplikasi yang berbeda.
  3. Message Routing: mengarahkan pesan ke tujuan yang sesuai, termasuk berdasarkan subject (publish-subscribe).
Soal No. 5 Koordinasi (15 poin)
Total: 15 Poin
a. Election Algorithm (5 poin)

Election algorithm adalah algoritma untuk memilih satu proses sebagai coordinator atau leader dalam sistem terdistribusi, biasanya ketika coordinator sebelumnya mengalami kegagalan.

Contoh: Bully Algorithm.

Cara kerja:

  1. Proses mendeteksi coordinator mengalami kegagalan.
  2. Proses mengirim pesan election kepada proses lain dengan ID lebih tinggi.
  3. Jika tidak ada respons, proses tersebut menjadi coordinator.
  4. Jika ada respons, proses menunggu proses dengan ID lebih tinggi melanjutkan election.
  5. Proses aktif dengan ID tertinggi akan menjadi coordinator dan mengirim pesan pemberitahuan kepada proses lain.
b. Vector Clock (8 poin)

Vector clock digunakan untuk menentukan urutan kausal (causal ordering) antar-event dalam sistem terdistribusi.

Aturan:

  1. Setiap proses memiliki vector clock yang awalnya [0,0,0].
  2. Setiap event lokal atau pengiriman pesan menambah nilai komponen proses tersebut sebesar 1.
  3. Saat menerima pesan, lakukan perbandingan nilai maksimum antara vector lokal dan vector pesan, kemudian tambahkan 1 pada komponen proses penerima.

Diagram Ruang-Waktu Vector Clock untuk P1, P2, P3

Hasil timestamp setiap event:

Proses Event Vector Clock
P1 b [1,1,0]
P1 c [2,1,0]
P1 d [3,1,0]
P1 e [4,1,0]
P2 a [0,1,0]
P2 f [2,2,0]
P2 g [2,3,0]
P3 h [2,3,1]
P3 i [4,3,2]

Keterangan:

  • a mengirim m1, kemudian b menerima m1.
  • c mengirim m3, kemudian f menerima m3.
  • e mengirim m2, kemudian i menerima m2.
  • g mengirim m4, kemudian h menerima m4.
  • d merupakan event internal pada P1.
c. Hubungan Kausal m2 dan m4 (2 poin)

Tidak, m2 dan m4 tidak saling bergantung secara kausal (concurrent).

Alasannya, timestamp kedua event pengiriman adalah:

  • m2 = [4,1,0]
  • m4 = [2,3,0]

Keduanya tidak dapat dibandingkan secara kausal karena komponen m2 lebih besar pada P1, sedangkan m4 lebih besar pada P2.

Dengan demikian, tidak terdapat hubungan happened-before antara m2 dan m4.

Soal No. 6 Penamaan (15 poin)
Total: 15 Poin
a. Perbedaan Flat Naming, Structured Naming, dan Attribute-Based Naming (5 poin)
  1. Flat Naming: menggunakan nama atau identifier tanpa struktur hierarkis. Pencarian dilakukan untuk menemukan lokasi entitas berdasarkan identifier.
  2. Structured Naming: menggunakan nama yang memiliki struktur hierarkis berupa node dan directory, sehingga pencarian dilakukan dengan menelusuri struktur nama.
  3. Attribute-Based Naming: mencari entitas berdasarkan atribut atau karakteristik tertentu, bukan berdasarkan nama atau identifier secara langsung.
b. Contoh Aplikasi Setiap Skema Penamaan (5 poin)
  1. Flat Naming: Chord (DHT), digunakan untuk mencari node atau data berdasarkan identifier melalui logical ring.
  2. Structured Naming: DNS (Domain Name System), digunakan untuk menerjemahkan nama domain menjadi alamat IP melalui struktur hierarkis.
  3. Attribute-Based Naming: LDAP (Lightweight Directory Access Protocol), digunakan untuk mencari pengguna berdasarkan atribut seperti nama, departemen, atau organisasi.
c. Perbedaan Iterative dan Recursive Name Resolution (5 poin)
  1. Iterative Name Resolution: client menghubungi name server secara bertahap. Jika server tidak memiliki informasi, server memberikan referensi ke server berikutnya untuk dihubungi client.
  2. Recursive Name Resolution: client mengirim permintaan ke satu name server, kemudian server tersebut meneruskan pencarian ke server lain hingga informasi ditemukan dan hasil dikembalikan ke client.

Perbedaan utama: pada iterative, client melanjutkan pencarian, sedangkan pada recursive, name server yang melanjutkan pencarian.

Soal No. 7 Konsistensi dan Fault Tolerant (15 poin)
Total: 15 Poin
a. Sequential Consistency (5 poin)
P1 R(x)a W(x)c
P2 W(x)a W(x)b
P3 R(x)c R(x)b
P4 R(x)c R(x)b

Ya, gambar tersebut sequentially consistent.

Alasannya, seluruh operasi dapat disusun dalam satu urutan global yang tetap mempertahankan urutan operasi setiap proses.

Urutan yang memungkinkan:

  1. P2: W(x)a
  2. P1: R(x)a
  3. P1: W(x)c
  4. P3: R(x)c
  5. P4: R(x)c
  6. P2: W(x)b
  7. P3: R(x)b
  8. P4: R(x)b

Urutan tersebut valid karena seluruh proses membaca nilai sesuai urutan write yang terjadi, tanpa melanggar urutan program masing-masing proses.

b. Causal Consistency (5 poin)
P1 R(x)a W(x)c
P2 W(x)a W(x)b
P3 R(x)a R(x)b R(x)c
P4 R(x)a R(x)c R(x)b

Ya, gambar tersebut causally consistent.

Alasannya:

  1. W(x)a terjadi sebelum W(x)b pada P2.
  2. P1 membaca nilai a, kemudian melakukan W(x)c.
  3. Dengan demikian, W(x)a memiliki hubungan kausal dengan W(x)b dan W(x)c.
  4. W(x)b dan W(x)c tidak memiliki hubungan kausal satu sama lain sehingga dapat terlihat dalam urutan berbeda.

P3 membaca a → b → c, sedangkan P4 membaca a → c → b.

Hal tersebut diperbolehkan karena W(x)b dan W(x)c merupakan concurrent writes.

c. Konsistensi untuk Electronic Stock Market (5 poin)

Saya memilih Linearizability karena electronic stock market membutuhkan konsistensi data yang kuat dan real-time.

Alasannya:

  1. Seluruh pengguna harus melihat harga saham dan order book yang konsisten.
  2. Setiap transaksi harus mengikuti urutan waktu nyata.
  3. Mencegah transaksi menggunakan informasi harga yang sudah tidak berlaku.
  4. Setiap operasi seolah-olah terjadi secara atomic pada satu titik waktu.

Dengan demikian, Linearizability membantu menjaga konsistensi harga dan transaksi meskipun terdapat banyak pengguna yang mengakses sistem secara bersamaan.
