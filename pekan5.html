Bagian 1

Sinkronisasi Jam Fisik (Physical Clocks)

Penyimpangan osilator kristal kuarsa, Universal Coordinated Time (UTC), dan protokol NTP.

Karena osilator perangkat keras pada setiap komputer mengalami fenomena Clock Drift (berjalan sedikit lebih cepat atau lebih lambat dari waktu ideal dengan batas laju drift ρ), jam komputer akan perlahan saling menjauh.

Konsep 1

Precision (Internal Sync)

Mengukur seberapa dekat waktu antarmesin yang berbeda dalam sistem: |Cp(t) - Cq(t)| ≤ π. Tujuannya menjaga keselarasan antarnode tanpa perlu peduli waktu matahari dunia nyata.

Konsep 2

Accuracy (External Sync)

Mengukur seberapa dekat jam komputer dengan waktu standar internasional atomik sebenarnya (UTC): |Cp(t) - t| ≤ α.

Network Time Protocol (NTP): 4 Timestamp Estimasi

NTP mengukur pertukaran pesan antara klien dan server dengan 4 penanda waktu:
T1 (klien kirim request) → T2 (server terima) → T3 (server kirim response) → T4 (klien terima response).
Relative Offset (θ): [ (T2 - T1) + (T3 - T4) ] / 2
Round-Trip Delay (δ): [ (T4 - T1) - (T3 - T2) ] / 2
NTP memilih pasangan nilai offset (θ) yang memiliki delay (δ) paling minimum untuk meminimalkan ketidakpastian jitter jaringan.

Bagian 2

Jam Logis: Lamport & Vector Clocks

Menentukan kausalitas dan urutan parsial kejadian tanpa memerlukan jam fisik global.

Relasi Happened-Before (a → b)

Diusulkan oleh Leslie Lamport, relasi kausal a → b menyatakan bahwa kejadian a terjadi sebelum dan berpotensi memengaruhi kejadian b:

  • Jika a dan b terjadi di proses yang sama dan a mendahului b, maka a → b.
  • Jika a adalah pengiriman pesan dan b adalah penerimaan pesan tersebut, maka a → b.
  • Transitivitas: Jika a → b dan b → c, maka a → c.
  • Jika tidak ada relasi kausal antardua kejadian, maka kejadian tersebut bersifat Konkuren (a || b).

Aturan Pembaruan Lamport Logical Clock

  1. Sebelum proses Pi mengeksekusi suatu kejadian internal, jam lokal dinaikkan: Ci = Ci + 1.
  2. Saat mengirim pesan m, proses menyertakan nilai jamnya: ts(m) = Ci.
  3. Saat proses Pj menerima pesan m, ia memperbarui jam lokalnya dengan nilai terbesar: Cj = max(Cj, ts(m)) + 1.
Kelemahan Lamport Clocks & Solusi Vector Clocks

Pada Lamport Clock, jika a → b maka dijamin C(a) < C(b). Namun kebalikannya tidak berlaku! Jika C(a) < C(b), kita tidak dapat memastikan apakah a → b atau keduanya konkuren.
Vector Clocks memecahkan kelemahan ini. Setiap proses memegang array vektor jam Vi[1..n]. Pada Vector Clocks berlaku relasi dua arah: a → b jika dan hanya jika V(a) < V(b), sehingga kausalitas sejati dapat dideteksi secara sempurna!

Bagian 3

Mutual Exclusion dalam Sistem Terdistribusi

Mencegah benturan akses bersamaan ke Critical Section (CS) tanpa memori fisik bersama.

Algoritma Mekanisme Kerja Jumlah Pesan Masuk CS Kelemahan Utama
Centralized Algorithm Satu koordinator tunggal mengelola izin. Proses mengirim REQUEST, koordinator menjawab GRANT, proses keluar mengirim RELEASE. 3 pesan (Request, Grant, Release). Single Point of Failure (koordinator mati = macet total) dan bottleneck beban.
Distributed (Ricart & Agrawala) Memanfaatkan Lamport timestamp. Proses mengirim request ke SEMUA node lain. Node lain membalas OK jika tidak berniat masuk atau timestamp-nya lebih besar. Masuk CS setelah menerima OK dari semua node. 2 × (N - 1) pesan. Jika salah satu node mengalami crash, seluruh sistem akan terblokir menunggu jawaban dari node yang mati tersebut (N point of failure!).
Token Ring Algorithm Node diatur dalam cincin logis. Token beredar melintasi ring. Hanya pemegang token yang berhak masuk ke CS. 1 hingga (N - 1) pesan (atau 0 jika sudah pegang). Jika token hilang (loss), dibutuhkan algoritma rumit untuk mendeteksi hilangnya token dan membuat token baru; jika ring putus perlu rekonstruksi.
Bagian 4

Algoritma Pemilihan (Election Algorithms)

Bagaimana node-node memilih koordinator baru ketika koordinator lama mengalami kegagalan.

Setiap proses diasumsikan memiliki Identifier unik. Prinsip dasarnya adalah memilih proses aktif yang memiliki identifier paling tinggi sebagai koordinator baru.

Algoritma 1

The Bully Algorithm

Ketika proses P mendeteksi koordinator mati, P mengirim pesan ELECTION ke semua proses ber-ID lebih tinggi.
- Jika ada node ber-ID lebih tinggi yang menjawab OK, node tersebut mengambil alih pemilihan dan P mundur.
- Jika tidak ada balasan dalam batas timeout, proses P menang dan memproklamirkan dirinya sebagai koordinator dengan menyiarkan pesan COORDINATOR ke semua node.

Algoritma 2

The Ring Algorithm

Node disusun dalam cincin logis searah jarum jam.
- Proses inisiator mengirim pesan ELECTION ke tetangga berikutnya yang memuat ID dirinya.
- Setiap node penerima menyisipkan ID-nya ke daftar pesan lalu meneruskannya.
- Begitu pesan kembali ke inisiator, node dengan ID tertinggi di daftar resmi menjadi koordinator baru, lalu pesan COORDINATOR diedarkan melintasi ring.

Bagian 5

Gossip Coordination & Sistem Lokasi

Agregasi terdesentralisasi, gossip peer-sampling, dan estimasi posisi node.

Gossip-Based Information Aggregation

Protokol gossip dapat digunakan untuk menghitung nilai agregat global (seperti rata-rata nilai sensor atau estimasi total jumlah node dalam jaringan) secara terdesentralisasi murni. Setiap putaran, sepasang node acak saling bertukar nilai dan memperbarui nilai masing-masing dengan rata-ratanya: (vp + vq) / 2. Dalam beberapa putaran pertukaran, seluruh node di jaringan akan secara eksponensial konvergen ke nilai rata-rata global yang sebenarnya!

Bagian 6

Lembar Rangkuman Cepat (Exam Cheat Sheet)

Pembeda utama konsep koordinasi untuk persiapan ujian UTS.

Pasangan Konsep Pembeda Utama untuk Ujian
Precision vs Accuracy Deviasi waktu antarmesin dalam sistem (≤ π) vs Deviasi waktu terhadap jam atomik UTC sebenarnya (≤ α).
Internal vs External Sync Sinkronisasi untuk menjaga presisi antarnode vs Sinkronisasi dengan sumber waktu UTC luar.
Lamport Clocks vs Vector Clocks a → b menjamin C(a) < C(b) (satu arah) vs a → b ⇔ V(a) < V(b) (dua arah mendeteksi kausalitas pasti).
Centralized vs Distributed Mutual Exclusion 3 pesan per masuk CS, single failure vs 2*(N-1) pesan per masuk CS, 1 node mati melumpuhkan semua.
Bully Algorithm vs Ring Algorithm Node ber-ID tinggi 'mengintimidasi' node lebih rendah vs Pesan pemilihan diedarkan melintasi cincin menyusun daftar node aktif.
