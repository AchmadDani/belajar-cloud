Bagian 1

Fondasi Komunikasi & Lapisan Middleware

Penyederhanaan model jaringan berlapis menuju arsitektur berorientasi middleware.

Transport Layer: TCP vs UDP dalam Sistem Terdistribusi

Untuk sebagian besar sistem terdistribusi, interface tingkat terendah yang berinteraksi langsung adalah Transport Layer:

Protokol 1

TCP (Transmission Control Protocol)

Bersifat connection-oriented, reliable (menjamin urutan dan keutuhan paket dengan mekanisme acknowledgment/retransmission), dan berbasis stream byte berkelanjutan.

Protokol 2

UDP (User Datagram Protocol)

Bersifat connectionless dan unreliable (best-effort). Tidak menjamin urutan kedatangan paket, namun memiliki overhead minimal dan latensi sangat rendah.

Peran Krusial Middleware Layer

Middleware bertindak sebagai lapisan perekat umum (*common protocols and services*) yang menyediakan:
1. Communication Protocols: Menyediakan abstraksi RPC, MOM, dan streaming.
2. (Un)marshaling Data: Mengubah struktur data memori lokal menjadi format biner jaringan (*marshaling*) dan merekonstruksinya di penerima (*unmarshaling*).
3. Naming & Security Protocols: Menemukan alamat resource dan mengenkripsi kanal.
4. Scaling Mechanisms: Mengelola replikasi data dan caching secara transparan.

Bagian 2

Tipe Komunikasi: Persistensi & Sinkronisasi

Dimensi persistensi penyimpanan pesan dan titik sinkronisasi pengirim.

Dimensi 1: Persistent vs Transient Communication

Persistent Communication: Pesan yang dikirim akan disimpan oleh sistem perantara (message queue) selama yang dibutuhkan sampai penerima siap mengambilnya. Pengirim dan penerima tidak perlu aktif bersamaan (contoh: Email, Antrean Pesan).
Transient Communication: Pesan hanya disimpan selama aplikasi pengirim dan penerima sedang aktif berjalan. Jika transmisi gagal atau penerima sedang mati, pesan akan langsung dibuang (contoh: Socket TCP, UDP).

Dimensi 2: Synchronous vs Asynchronous Communication

Asynchronous Communication: Pengirim langsung melanjutkan eksekusinya segera setelah menyerahkan pesan ke buffer komunikasi lokal.
Synchronous Communication: Pengirim terblokir (*blocked*) dan harus menunggu pada titik sinkronisasi:

  • Sync at request submission: Pengirim menunggu sampai pesan berhasil masuk ke middleware lokal.
  • Sync at request delivery: Pengirim menunggu sampai pesan tiba di mesin penerima.
  • Sync at response (RPC): Pengirim menunggu sampai server selesai memproses dan mengembalikan hasil jawaban.
Kombinasi Komunikasi Karakteristik & Mekanisme Contoh Nyata
Persistent Asynchronous Pesan disimpan di antrean, pengirim langsung melanjutkan pekerjaan tanpa menunggu. Message Queuing Systems (RabbitMQ, Apache Kafka, AMQP).
Persistent Synchronous Pesan disimpan di antrean, namun pengirim menunggu konfirmasi bahwa pesan telah tersimpan di buffer server. Sistem pertukaran dokumen resmi finansial dengan ACK tanda terima.
Transient Asynchronous Pesan dibuang jika gagal sampai, pengirim tidak menunggu (kirim dan lupakan / fire-and-forget). Pengiriman datagram UDP, streaming sensor suhu kontinu.
Transient Synchronous Pesan dibuang jika jaringan putus, pengirim terblokir menunggu jawaban dari server. Traditional Client-Server RPC dan HTTP Request-Response.
Bagian 3

Remote Procedure Call (RPC)

Mekanisme pemanggilan fungsi pada mesin jarak jauh seolah-olah fungsi lokal.

Duo Komponen: Client Stub & Server Stub (Skeleton)

Client Stub: Berada di mesin klien. Menyamar sebagai fungsi asli yang dipanggil program klien. Tugasnya mengemas nama prosedur dan parameter menjadi paket pesan jaringan melalui Marshaling, lalu mengirimkannya ke server.
Server Stub (Skeleton): Berada di mesin server. Menerima paket pesan, melakukan Unmarshaling untuk merekonstruksi parameter asli, memanggil fungsi sesungguhnya di server, lalu mengemas nilai balikan (*return value*) untuk dikirim kembali ke klien.

Alur 10 Langkah Kerja RPC Klasik

  1. Klien memanggil fungsi pada Client Stub lokal seperti panggilan fungsi biasa.
  2. Client Stub menyusun pesan jaringan berisi nama prosedur dan argumen (Marshaling).
  3. Client Stub menyerahkan pesan ke Operating System lokal klien.
  4. OS lokal mengirimkan pesan melintasi jaringan ke server jarak jauh.
  5. OS server menerima pesan dan meneruskannya ke Server Stub.
  6. Server Stub membongkar parameter dari pesan jaringan (Unmarshaling).
  7. Server Stub memanggil fungsi prosedur yang sebenarnya di server.
  8. Fungsi server menyelesaikan tugas dan mengembalikan hasil ke Server Stub.
  9. Server Stub mengemas hasil balikan ke dalam pesan dan mengirimkannya kembali via OS.
  10. Client Stub menerima pesan balasan, membongkarnya, dan mengembalikan hasil ke program klien.
Tantangan Parameter Passing: Pointers & Remote References

Pass by value sangat mudah dilakukan karena nilai disalin ke pesan. Namun Pass by reference (Pointer) sangat sulit karena pointer merujuk ke alamat memori fisik lokal mesin klien yang tidak ada artinya di mesin server. Solusinya: menyalin seluruh blok data yang ditunjuk pointer (*deep copy*), atau membuat Remote Object Reference khusus yang didukung middleware.

Asynchronous RPC: Memangkas Waktu Tunggu Klien

Pada RPC konvensional, klien terhenti menunggu server menyelesaikan seluruh tugasnya. Pada Asynchronous RPC, klien hanya menunggu sampai server mengirim sinyal bahwa request telah berhasil diterima (*Acknowledgment / ACK*). Begitu ACK diterima, klien langsung melanjutkan proses lokalnya tanpa menunggu hasil komputasi selesai!

Bagian 4

Message-Oriented: MOM, Sockets & ZeroMQ

Komunikasi berbasis antrean pesan persisten dan soket pesan tingkat tinggi.

1. Transient Messaging: Berkeley Sockets & ZeroMQ

Soket adalah abstraksi endpoint komunikasi. Urutan primitif socket TCP standar: socket() → bind() → listen() → accept() pada server, dan connect() pada klien.

ZeroMQ menyediakan soket cerdas tingkat tinggi yang menyembunyikan detail koneksi TCP dan mendukung pola arsitektur:

Request-Reply Pattern: Pasangan soket REQ dan REP untuk komunikasi dua arah sinkron mirip RPC.
Publish-Subscribe: Soket PUB memancarkan pesan ke banyak soket SUB berdasarkan kecocokan filter prefix.
Pipeline (Push-Pull): Soket PUSH mendistribusikan beban kerja secara seimbang ke beberapa pekerja soket PULL.

2. Persistent Messaging: Message-Oriented Middleware (MOM)

MOM menjamin pesan tidak hilang meskipun aplikasi penerima sedang mati atau jaringan sedang terputus:

  • Message Queue: Buffer penyimpanan pesan persisten dengan urutan tertentu.
  • Queue Manager: Komponen perangkat lunak yang mengelola antrean dan merutekan pesan antar-antrean.
  • Message Broker: Komponen penengah yang mengatasi perbedaan format data heterogen antaraplikasi dengan menerjemahkan skema pesan (menggunakan aturan transformasi) sehingga aplikasi yang sama sekali berbeda teknologi tetap dapat bertukar data.
  • AMQP (Advanced Message Queuing Protocol): Standar protokol terbuka industri untuk antrean pesan enterprise.
Bagian 5

Multicast & Gossip-Based Dissemination

Penyebaran data satu-ke-banyak di tingkat aplikasi dan protokol epidemiologi.

Application-Level Multicasting (ALM)

Karena router IP publik jarang mengaktifkan multicast level jaringan, penyebaran data dilakukan pada overlay network tingkat aplikasi.

Dua Metrik Evaluasi Kualitas ALM

1. Link Stress: Mengukur berapa kali salinan paket pesan yang identik melintasi link fisik jaringan yang sama. Nilai link stress ideal adalah 1.
2. Stretch (Relative Delay Penalty / RDP): Rasio antara waktu latensi delay transmisi melalui jalur ALM di overlay dibandingkan dengan delay jalur langsung di level jaringan IP fisik (Stretch = DelayALM / DelayIP).

Gossip-Based (Epidemic) Protocols

Meniru penyebaran virus atau rumor di masyarakat untuk menyinkronkan data antar-replika server:

Mekanisme Cara Operasi Efektivitas Penyebaran
Push Approach Node yang memiliki pembaruan mengirimkannya ke node acak lain. Sangat cepat ketika jumlah node terinfeksi masih sedikit, namun lambat saat sebagian besar node sudah terupdate.
Pull Approach Node secara berkala meminta update terbaru dari node acak lain. Sangat efektif dan cepat ketika sebagian besar node jaringan sudah memiliki update.
Push-Pull Approach Node saling bertukar update secara timbal balik dalam satu siklus kontak. Paling optimal dan paling cepat mencapai konsistensi konvergen global.
Death Certificate: Menghapus Data pada Protokol Gossip

Pada sistem epidemi, jika sebuah data langsung dihapus dari memori server A, server B yang masih memiliki data lama akan menganggap server A belum menerima data tersebut dan "menularkan" kembali data tersebut ke server A! Solusinya adalah menerbitkan Death Certificate (Tombstone): penanda khusus bertanggal yang mencatat bahwa data telah dihapus, sehingga penghapusan tersebut dapat disebarkan secara teratur ke seluruh node sebelum sertifikatnya kedaluwarsa.

Bagian 6

Lembar Rangkuman Cepat (Exam Cheat Sheet)

Pembeda utama konsep komunikasi sistem terdistribusi untuk persiapan ujian UTS.

Pasangan Konsep Pembeda Utama untuk Ujian
Transient vs Persistent Communication Pesan dibuang jika penerima tidak aktif vs Pesan disimpan di antrean perantara sampai berhasil diterima.
Synchronous vs Asynchronous Communication Pengirim terblokir menunggu titik sinkronisasi respon vs Pengirim langsung lanjut bekerja setelah pesan diserahkan ke buffer.
Marshaling vs Unmarshaling Mengubah struktur data memori lokal menjadi paket biner jaringan vs Mengembalikan paket biner ke struktur data memori penerima.
Client Stub vs Server Stub Menyamar sebagai fungsi lokal di sisi klien & lakukan marshaling vs Menerima pesan di server, unmarshaling, & memanggil fungsi asli.
Asynchronous RPC Klien hanya menunggu sinyal penerimaan pesan (ACK) dari server, bukan menunggu hasil perhitungan tuntas.
Message Broker vs Queue Manager Mengatasi heterogenitas data dengan mentransformasi format isi pesan vs Mengatur antrean buffer dan routing rute pesan.
Link Stress vs Stretch (RDP) Berapa kali paket identik melewati link fisik yang sama vs Rasio waktu delay jalur ALM terhadap jalur jaringan fisik IP.
Push vs Pull Gossip Pengirim aktif menawarkan data vs Penerima aktif meminta data (Pull lebih cepat di akhir epidemi).
Death Certificate Penanda penghapusan (tombstone) agar data yang telah dihapus tidak dibangkitkan kembali oleh node tetangga.
