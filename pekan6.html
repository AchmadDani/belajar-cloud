Bagian 1

Konsep Dasar Naming

Pembeda fundamental antara Name, Identifier, dan Address serta independensi lokasi.

Tipe 1

Name

Label berupa string simbolik yang digunakan oleh manusia atau aplikasi untuk merujuk pada suatu entitas (contoh: www.informatika.ac.id).

Tipe 2

Identifier

Nama unik yang memenuhi 3 sifat wajib: (1) Merujuk paling banyak 1 entitas, (2) Setiap entitas memiliki paling banyak 1 identifier, (3) Identifier tidak pernah didaur ulang/digunakan kembali untuk entitas lain.

Tipe 3

Address

Nama dari Access Point suatu entitas yang mendefinisikan lokasi jaringan tempat entitas tersebut dapat diakses (contoh: alamat IP dan nomor Port).

Location Independence & Pure Names

Location Independence: Nama entitas tidak bergantung pada lokasi fisiknya, sehingga entitas bebas berpindah mesin tanpa harus mengganti namanya.
Pure Name: Nama acak murni yang sama sekali tidak mengandung informasi mengenai lokasi atau karakteristik entitas, melainkan murni referensi acak (seperti UUID 128-bit).

Bagian 2

Flat Naming (Nama Tanpa Struktur)

Mencari lokasi entitas berdasarkan identifier yang tidak memiliki hierarki.

Pendekatan Flat Naming Mekanisme Kerja Kelebihan & Kekurangan
1. Broadcasting Mengirim pesan pencarian ke seluruh node di jaringan lokal (contoh: ARP untuk mencari MAC Address dari IP Address). Sederhana, tidak butuh server pusat. Namun boros bandwidth dan tidak bisa diskalakan di jaringan WAN.
2. Forwarding Pointers Ketika entitas berpindah dari node A ke B, node A meninggalkan pointer referensi menuju B. Jika pindah ke C, B menunjuk ke C. Mendukung mobilitas cepat. Namun rantai pointer dapat menjadi sangat panjang, lambat ditelusuri, dan putus jika satu node mati.
3. Home-Based Approach Entitas memiliki lokasi 'rumah' tetap (Home Location). Setiap kali berpindah, entitas mendaftarkan Care-of Address ke Home (contoh: Mobile IP). Tidak butuh rantai panjang. Namun timbul masalah rute segitiga (*triangle routing*) yang menambah latensi.
4. Distributed Hash Tables (DHT) Memetakan identifier dan node ke dalam ruang kunci numerik terstruktur seperti Chord Ring. Sangat terdesentralisasi, tidak ada single failure, lookup efisien logaritmik O(log N).
Bagian 3

Structured Naming & Domain Name System (DNS)

Pohon ruang nama (Name Space Graph), resolusi nama iteratif vs rekursif, dan arsitektur DNS.

Name Space Graph & Closure Mechanism

Ruang nama terstruktur dimodelkan sebagai graf berarah dengan Root Node, Directory Nodes (memiliki tabel tepi menuju node lain), dan Leaf Nodes (entitas akhir).
Closure Mechanism: Menentukan konteks awal di mana proses resolusi nama harus dimulai (misal: bagaimana sistem tahu bahwa / adalah root filesystem atau . adalah root DNS).

Resolusi Nama: Iterative vs Recursive

Resolusi 1

Iterative Name Resolution

Klien mengontak server DNS tingkat atas, server mengembalikan alamat server DNS tingkat berikutnya, lalu klien sendiri yang menghubungi server berikutnya secara berulang sampai selesai. Beban kerja berada di sisi klien resolver.

Resolusi 2

Recursive Name Resolution

Klien bertanya ke server DNS pertama, lalu server tersebut yang mengontak server lain secara berantai atas nama klien dan meneruskan hasil akhir kembali ke klien. Memudahkan caching di server, tetapi membebani server DNS tingkat atas.

3 Lapisan Hirarki DNS & Resource Records

Lapisan DNS Karakteristik & Contoh Tingkat Stabilitas Data
Global Layer Root server dan server Top-Level Domain (TLD seperti .com, .id, .org). Sangat stabil, dikelola oleh registrar resmi, jarang sekali berubah.
Administrational Layer Server nama organisasi atau institusi (contoh: ugm.ac.id, google.com). Cukup stabil, dikelola oleh administrator jaringan organisasi.
Managerial Layer Server lokal departemen yang memetakan host individual (contoh: workstation lab). Sering berubah seiring penambahan atau perpindahan perangkat klien.
Tipe DNS Resource Records (RR) Populer

A: Memetakan nama host ke alamat IPv4 (32-bit).
AAAA: Memetakan nama host ke alamat IPv6 (128-bit).
NS: Menyimpan nama otoritatif Name Server untuk zona tersebut.
CNAME: Menyimpan nama alias kanonikal dari suatu host.
MX: Mengarahkan pengiriman email ke Mail Exchange server.

Bagian 4

Attribute-Based Naming (Direktori & LDAP)

Pencarian entitas berdasarkan karakteristik atau atribut, bukan sekadar nama tetap.

Terkadang pengguna tidak mengetahui nama persis suatu printer atau server, melainkan hanya atributnya (contoh: "cari printer warna duplex di lantai 2"). Inilah fungsi Directory Services.

Lightweight Directory Access Protocol (LDAP)

Data disusun dalam hierarki Directory Information Tree (DIT):
- Relative Distinguished Name (RDN): Nama unik lokal pada level hierarki saat ini (contoh: cn=Ahmad Fauzi).
- Distinguished Name (DN): Jalur lengkap dari akar pohon hingga entitas (contoh: cn=Ahmad Fauzi, ou=Informatika, o=Universitas, c=ID).

Bagian 5

Lembar Rangkuman Cepat (Exam Cheat Sheet)

Pembeda utama konsep penamaan sistem terdistribusi untuk persiapan ujian UTS.

Pasangan Konsep Pembeda Utama untuk Ujian
Name vs Identifier vs Address Nama simbolik acuan manusia vs ID unik 1-ke-1 tanpa daur ulang vs Lokasi access point jaringan entitas.
Location Independence Kemampuan entitas berpindah lokasi fisik tanpa harus mengganti nama resminya.
Iterative vs Recursive DNS Resolution Klien resolver aktif menghubungi server tiap tingkatan sendiri vs Server DNS yang meneruskan pertanyaan berantai atas nama klien.
Global vs Managerial DNS Layer Lapisan Root & TLD yang sangat jarang berubah vs Lapisan host lokal departemen yang dinamis dan sering berubah.
DNS Record: A vs CNAME vs MX Pemetaan IP address vs Nama alias kanonikal vs Mail server email.
RDN vs DN pada LDAP Atribut unik di satu level hierarki lokal vs Rantai hierarki lengkap dari root DIT.

Apa itu Closure Mechanism?

Mekanisme yang menentukan konteks awal di mana proses resolusi nama harus dimulai (misal bagaimana proses mengetahui alamat IP server DNS root awal).

Klik untuk melihat jawaban & kata kunci

Kelemahan Rantai Forwarding Pointers

Rantai penunjuk dapat bertambah panjang seiring seringnya entitas berpindah lokasi, memperlambat proses pencarian dan rentan putus total jika satu node di tengah rantai mengalami crash.

Perbedaan Iterative vs Recursive DNS Resolution

Iterative: Klien yang secara aktif menghubungi setiap DNS server langkah demi langkah.
Recursive: Server DNS pertama yang menjadi perantara menghubungi server-server lain secara estafet.
