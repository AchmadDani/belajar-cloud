Bagian 1

Gaya Arsitektur & Layering Sistem

Pondasi penyusunan sistem berdasarkan komponen, koneksi, pertukaran data, dan susunan konfigurasi.

Empat Aspek Architectural Styles

Architectural Style menggambarkan bagaimana sistem terdistribusi disusun berdasarkan empat aspek:

Aspek 1 & 2

Components & Connections

Components: Bagian penyusun sistem yang dapat diganti (replaceable) dengan interface jelas.
Connections: Cara komponen saling terhubung dan berkomunikasi.

Aspek 3 & 4

Data Exchange & Config

Data Exchange: Informasi atau pesan yang dipertukarkan antarkomponen.
Configuration: Cara komponen dan penghubungnya disusun bersama membentuk satu kesatuan sistem.

Apa itu Connector?

Mekanisme yang menjadi perantara komunikasi, koordinasi, atau kerja sama antarkomponen. Contoh konektor nyata dalam sistem terdistribusi meliputi: Remote Procedure Call (RPC), Messaging, dan Streaming data.

Layered Architecture: Organisasi Pemanggilan

Sistem dibagi menjadi beberapa lapisan hierarkis. Komunikasi antarlapisan dapat berbentuk:

  • Request/Response Downcall: Permintaan diteruskan dari layer yang lebih tinggi ke layer di bawahnya, dan balasan dikembalikan melalui jalur sebaliknya.
  • One-way Call: Pemanggilan dilakukan ke layer berikutnya tanpa harus menunggu respons langsung.
  • Upcall: Layer yang lebih rendah memanggil kembali fungsi pada layer yang lebih tinggi (mirip callback handler).
Trisula Konsep: Protocol vs Service vs Interface

1. Protocol: Kumpulan aturan yang mengatur bagaimana dua entitas pada layer yang sama (setara) saling bertukar pesan.
2. Service: Layanan operasional yang disediakan oleh suatu layer untuk digunakan oleh layer di atasnya.
3. Interface: Batas atau fasilitas teknis resmi untuk mengakses layanan dari layer di bawahnya.

Traditional Three-Layered View (Application Layering)

Standar de-facto pemisahan fungsional sistem informasi terdistribusi:

1. Application-Interface

Berinteraksi langsung dengan pengguna atau sistem eksternal (User Interface, Form input, Presentasi data).

2. Processing Layer

Memuat logika bisnis utama, algoritma perankingan, dan pembuatan kueri pemrosesan tanpa menyimpan data spesifik.

3. Data Layer

Menyimpan data persisten yang dimanipulasi aplikasi (DBMS relasional, NoSQL, atau File Storage).

Bagian 2

Service-Oriented & RESTful Architectures

Evolusi dari pendekatan berbasis objek menuju arsitektur berorientasi resource (REST).

Object-Based Style vs RESTful Architectures

Object-Based Style memandang sistem sebagai kumpulan objek yang saling memanggil prosedur/method lintas jaringan melalui enkapsulasi. Sebaliknya, RESTful Architectures memandang sistem sebagai kumpulan resource yang dimanipulasi melalui antarmuka HTTP standar.

4 Karakteristik Inti RESTful:

1. Single Naming Scheme: Seluruh resource diidentifikasi secara unik menggunakan URI seragam.
2. Uniform Interface: Seluruh service menggunakan operasi HTTP standar yang sama (PUT, GET, POST, DELETE).
3. Self-Descriptive Messages: Setiap pesan memiliki metadata dan konteks lengkap untuk diproses tanpa kebergantungan luar.
4. Stateless Interaction: Server tidak menyimpan status riwayat sesi klien untuk kebutuhan interaksi berikutnya.
HTTP Verb Fungsi Utama REST Contoh pada Amazon S3
PUT Membuat resource baru atau menimpa resource yang ada secara idempoten. Membuat Bucket baru atau mengunggah Object file ke URI bucket.
GET Mengambil kondisi representasi resource saat ini. Membaca isi file Object atau mendaftar daftar file di dalam Bucket.
POST Memodifikasi resource dengan mengirimkan data baru. Menambahkan entri metadata atau memproses unggahan dinamis.
DELETE Menghapus resource dari penyimpanan. Menghapus Object atau menghapus Bucket kosong.
Perbedaan Kunci: SOAP vs RESTful

SOAP (Simple Object Access Protocol): Berfokus pada pemanggilan operasi/method (contoh: bucket.create("mybucket")). Antarmuka tergantung fungsi yang didefinisikan service.
RESTful: Berfokus pada manipulasi resource melalui kata kerja HTTP standar terhadap URI (contoh: PUT https://mybucket.s3.amazonaws.com/). Lebih ringan dan sederhana, namun kompleksitas berpindah ke pengelolaan parameter request.

Bagian 3

Koordinasi, Coupling & Publish-Subscribe

Tingkat kebergantungan waktu dan referensi antarkomponen serta model Shared Data Space.

Temporal vs Referential Coupling

Coupling menggambarkan keterikatan komunikasi antarkomponen:

  • Temporal Coupling: Ketergantungan terhadap waktu atau ketersediaan aktif komponen lain saat komunikasi berlangsung.
  • Referential Coupling: Ketergantungan terhadap identitas atau alamat komponen tujuan komunikasi.
Temporal Coupling Referential Coupling Model Komunikasi Karakteristik & Penjelasan
Coupled (Terikat Waktu) Coupled (Terikat Alamat) Direct Kedua pihak harus aktif bersamaan dan saling mengetahui alamat tujuan langsung (contoh: RPC, Socket TCP).
Coupled (Terikat Waktu) Decoupled (Bebas Alamat) Mailbox Klien mengirim ke mailbox tanpa tahu siapa penerima pastinya, tetapi proses pengambilan tetap terikat waktu.
Decoupled (Bebas Waktu) Coupled (Terikat Alamat) Event-based Komunikasi melalui event ke tujuan spesifik. Komponen pengirim dan penerima tidak harus aktif bersamaan.
Decoupled (Bebas Waktu) Decoupled (Bebas Alamat) Shared Data Space Komponen berkomunikasi melalui ruang data bersama tanpa tahu alamat satu sama lain dan tanpa harus aktif bersamaan.

Linda Tuple Space: Operasi & Karakteristik

Linda adalah implementasi klasik Shared Data Space yang menyimpan data dalam bentuk tuple (sekumpulan nilai terstruktur).

Operasi 1

out(t)

Menambahkan tuple t ke dalam tuple space. Bersifat multiset (jika dipanggil dua kali, dua salinan tuple akan tersimpan).

Operasi 2

rd(t)

Membaca dan mengambil salinan tuple yang cocok dengan pola template t tanpa menghapusnya dari space. Bersifat blocking jika data belum ada.

Operasi 3

in(t)

Membaca sekaligus menghapus tuple yang cocok dari tuple space. Juga bersifat blocking jika tuple belum tersedia.

Pub-Sub: Topic-Based vs Content-Based Subscription

Topic-Based: Berlangganan berdasarkan kata kunci atau topik tertentu (pencocokan sederhana: attribute = value). Cepat dan efisien diskalakan.
Content-Based: Berlangganan berdasarkan kriteria rentang isi data (pencocokan kompleks: attribute ∈ range). Sangat fleksibel bagi subscriber, namun menimbulkan beban pencocokan tinggi yang berisiko terhadap skalabilitas sistem.

Bagian 4

Middleware, Wrapper & Broker

Mekanisme integrasi komponen legacy dan penyederhanaan kompleksitas koneksi antaraplikasi.

Middleware sering dijuluki sebagai OS of Distributed Systems karena menyediakan komponen, antarmuka seragam, dan fungsi komunikasi umum sehingga aplikasi tidak perlu mengimplementasikan ulang fungsi dasar tersebut.

Integrasi Komponen Legacy: Wrapper / Adapter

Ketika aplikasi baru perlu menggunakan sistem lama (legacy) yang antarmukanya tidak cocok, digunakan Wrapper / Adapter yang menerjemahkan panggilan aplikasi baru menjadi instruksi yang dipahami komponen legacy.

Aspek Analisis Pendekatan 1-on-1 (Point-to-Point) Pendekatan Broker (Terpusat)
Pola Komunikasi Langsung antaraplikasi. Setiap aplikasi membuat wrapper ke aplikasi mitra. Seluruh aplikasi berkomunikasi melalui entitas Broker tunggal.
Jumlah Wrapper (N aplikasi) N × (N - 1) 2N
Kompleksitas Komputasi O(N²) (Kuadratik, meledak saat aplikasi bertambah). O(N) (Linear, sangat efisien dan mudah dikelola).
Adaptable Middleware: Intercepting the Usual Flow of Control

Middleware menyediakan alur kendali standar. Untuk mendukung kebutuhan aplikasi khusus, arsitektur modern menggunakan mekanisme Interception: menyela alur eksekusi pesan standar untuk menyisipkan otorisasi khusus, logging, atau enkripsi sebelum pesan diteruskan ke komponen tujuan.

Bagian 5

Peer-to-Peer & Distribusi Simetris

Distribusi beban vertikal vs horizontal, serta arsitektur P2P terstruktur (Chord Ring) dan tidak terstruktur.

Tipe Distribusi 1

Vertical Distribution

Membagi sistem ke dalam logical layers yang berbeda fungsinya (Interface, Processing, Data), lalu menjalankan tiap layer pada server terpisah (contoh: Multi-Tier Client-Server).

Tipe Distribusi 2

Horizontal Distribution

Membagi sistem ke beberapa komponen yang memiliki fungsi setara secara logis, tetapi masing-masing komponen menangani pecahan data yang berbeda (contoh: Peer-to-Peer dan Sharding).

Structured P2P: Distributed Hash Table & Chord

Structured P2P menggunakan skema penempatan data berbasis kunci deterministik dengan fungsi hash: key = hash(value).

Prinsip Kerja Chord Ring

1. Node dan key data dipetakan ke dalam lingkaran logis berukuran 2m.
2. Aturan Penyimpanan: Data dengan key k disimpan pada node dengan identifier terkecil yang lebih besar atau sama dengan k (id ≥ k). Node ini disebut Successor dari key k.
3. Shortcut Links (Finger Table): Ring dilengkapi pintasan antar-node agar proses pencarian (lookup) berlangsung cepat secara logaritmik O(log N).

Unstructured P2P: Flooding vs Random Walk

Pada P2P tidak terstruktur, node membentuk graf acak (*overlay network*) tanpa aturan penempatan data yang kaku. Dua metode pencariannya adalah:

Metode Cara Kerja Kelebihan Kelemahan & Solusi
Flooding Node pengirim meneruskan request pencarian ke seluruh tetangganya secara serentak. Dapat menjangkau ribuan node dan menemukan data dengan sangat cepat. Boros bandwidth dan membebani jaringan. Wajib dibatasi dengan TTL (Time-To-Live) agar tidak berputar tanpa henti.
Random Walk Node pengirim hanya memilih satu tetangga acak untuk meneruskan request. Sangat hemat beban pesan komunikasi jaringan. Membutuhkan waktu lebih lama untuk menemukan data. Ekspektasi langkah pencarian: S ≈ N / r (berbanding terbalik dengan replika).
Super-Peer Networks & BitTorrent

Super-Peer: Node yang memiliki performa dan bandwidth lebih tinggi ditunjuk sebagai super-peer untuk mengelola indeks pencarian node biasa.
BitTorrent: Menggunakan Torrent File (metrik file), Tracker (pencatat peer aktif), Swarm (kelompok peer yang berbagi file), dan memecah file menjadi Chunks sehingga peer dapat saling barter potongan data secara terdistribusi.

Bagian 6

Hybrid: Cloud, Edge & Blockchain

Kombinasi model arsitektur modern dalam komputasi awan, tepi jaringan, dan buku besar terdistribusi.

4 Lapisan Cloud Computing

Cloud computing membagi abstraksi infrastrukturnya menjadi empat lapisan dari bawah ke atas:

  1. Hardware Layer: Perangkat fisik CPU, memori, switch jaringan, catu daya, dan pendingin data center.
  2. Infrastructure Layer: Virtualisasi server dan media penyimpanan virtual (IaaS).
  3. Platform Layer: Abstraksi tingkat tinggi untuk pengembangan dan penyimpanan data (PaaS, contoh: Amazon S3 Bucket API).
  4. Application Layer: Perangkat lunak akhir yang digunakan langsung oleh konsumen (SaaS, contoh: Office suites, Google Docs).

Edge Infrastructure & Orkestrasi

Edge server ditempatkan di perbatasan antara jaringan lokal organisasi dan Internet. Tiga aspek penting dalam Edge Orchestration:

  • Resource Allocation: Memastikan ketersediaan kapasitas komputasi di edge node.
  • Service Placement: Menentukan kapan dan di mana suatu layanan harus dijalankan mendekati pengguna mobile.
  • Edge Selection: Memilih node edge terbaik (catatan penting: node yang secara fisik paling dekat belum tentu memberikan konektivitas terbaik).

Blockchain: Mekanisme Konsensus Terdistribusi

Blockchain adalah struktur penyimpanan rantai blok append-only yang bersifat immutable (tidak dapat diubah) dan direplikasi masif.

Pendekatan Konsensus Otoritas Pengambil Keputusan Tingkat Partisipasi & Karakteristik
Centralized Satu entitas pusat tunggal menentukan validator. Kurang sesuai dengan filosofi desentralisasi blockchain.
Distributed (Permissioned) Kelompok server terpilih dalam jumlah terbatas. Konsensus tercapai selama minimal sekitar 2/3 server berperilaku jujur sesuai spesifikasi (menampung puluhan server).
Decentralized (Permissionless) Peserta jaringan secara kolektif memilih leader. Partisipasi terbuka untuk umum melalui pemilihan leader terdesentralisasi (Proof of Work / Proof of Stake).
